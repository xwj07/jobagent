# 岗位采集、匹配与人工评估

## 页面操作

1. 在首页上传并解析 PDF 简历。
2. 从下拉菜单选择职位、城市、平台，点击“获取岗位”。当前每个平台读取首批最多 5 个完整 JD。
   也可选择“自行提供”，上传文字版 PDF、UTF-8 TXT，或粘贴招聘信息。文件与文字二选一，职位名称可选。
3. 展开岗位描述核对内容，点击“生成匹配报告”。报告逐项列出命中、部分命中、简历未体现、原文证据和补足建议。
4. 进入“人工标注与评估”，由人工独立阅读简历和 JD，填写缺失技能及各维度满足率。
5. 保存后自动更新指标，可导出 JSONL 保存此次输入、模型预测与人工标签。

只有生成过报告的输入配对才会保存到本地 `match_cases` 表。相同的完整输入快照重复生成报告会更新当前预测，不会重复创建配对；人工标签保留。上传阶段不保存 PDF。

## 采集边界与当前验证结果

- 智联：读取公开搜索页内的 `__INITIAL_STATE__`，从职位列表提供的完整描述生成 JD，不把卡片摘要当完整岗位要求。已实测“Python / 杭州”成功取得 5 条完整 JD。
- BOSS：调用搜索入口后再获取职位详情。当前实测搜索返回 `code=37`“您的环境存在异常”，详情页跳转安全验证。页面会明确标记阻断，不生成虚假的岗位数据。BOSS 的成功分支已使用固定响应测试，尚未取得实际采集成功证据。
- 采集不登录账户、不解决验证码、不伪造安全参数；网站访问条件变化会显示具体失败原因。
- 两个平台的结果分别返回自己的状态。未取得完整 JD 的来源不进入匹配。

## 固定评分细则：match-v1

| 维度 | 基础权重 |
|---|---:|
| 技术技能 | 50% |
| 项目与业务经验 | 25% |
| 工作年限与职责 | 15% |
| 学历与专业 | 10% |

模型从 JD 拆解要求并核对证据，程序计算分数：

匹配请求向当前 Gitee DeepSeek 接口发送 `thinking.type=disabled`，直接生成结构化报告。
解释和建议各用一句话，保留全部独立要求与原文证据。

- 每项满足程度：命中 `1`、部分命中 `0.5`、简历未体现 `0`。
- 硬性要求的项权重为 `1`，优先或加分项为 `0.5`。
- 维度满足率 = `100 × Σ(项权重 × 满足程度) / Σ项权重`。
- 总分 = 各维度满足率按基础权重加权。JD 未要求的维度排除，剩余权重重新归一。

例如，JD 仅要求 Python、Kubernetes 和本科学历，两个技能都是硬性要求。简历只体现 Python，但学历符合，则技能满足率为 50，学历为 100，总分为 `(50×50+100×10)/(50+10)=58.33`。

程序将 JD 与结构化简历字段拆成带编号的原文片段，模型只选择对应片段编号；
报告中的引用由程序从原文复制，模型不再生成或改写引用。岗位与简历使用独立的证据列表，
简历姓名与求职意向不作为能力证明。没有简历证据的要求标为“简历未体现”，
不能直接复制 JD 的要求来充当候选人能力。不存在的证据编号仍会报出具体原因。
原文核对证明引用来自输入，不保证模型的语义判断一定正确，因此仍需要人工评估。

## 人工标注 50 组配对

当前没有预置黄金标签，网页会显示实际标注进度。

1. 收集真实、不同的简历与岗位配对；不要用重复请求或改写同一份数据凑 50 组。保留命中较高、中等、较低的样例。
2. 标注者依据原始资料独立判断。标注接口不返回该配对的模型报告或模型分数；最好让没有看过报告的人标注。
3. 技能 gap 的口径为：JD 明确要求的技术技能中，简历没有充分证据满足的项目，包含“部分命中”和“简历未体现”，同时包含硬性和加分要求。用单一通用技能名称记录。`K8s` 和 `Kubernetes` 会统一为 `kubernetes`。
4. 对“Python/Java 二选一”之类要求整体判断，任一个充分满足则不标 gap；全部不满足时标 `Python/Java`，不要当作两个独立硬性要求。
5. 人工按同一 rubric 填写各维度满足率；JD 未提出要求的维度取消勾选。人工综合分由程序合成，不能照抄模型分数。
6. 同一模型和 rubric 下积累至少 50 组完成标注的样例。未标注的数据不进入指标。不同模型或 rubric 版本分组计算，不能用混合的 50 组宣称单一版本已完成评估。
7. 修改提示词或模型前先导出当前数据。当前表保存每组配对的最新预测；不提供历史预测版本管理。

## 指标定义

先在每组配对内计算规范化技能名称集合，再跨配对累计：

- TP：模型与人工都标为 gap。
- FP：模型标为 gap，人工没有标。
- FN：人工标为 gap，模型漏掉。
- Precision = `TP/(TP+FP)`。
- Recall = `TP/(TP+FN)`。
- F1 = `2TP/(2TP+FP+FN)`。

这属于 micro 统计；同一技能出现在不同配对中按不同判断计数。分母为零时显示“不可计算”，不伪造为零或满分。

Spearman ρ 先对模型分数、人工分数分别排序，同分使用平均秩，再计算两组秩的 Pearson 相关系数。不足两组数据或任一方分数全部相同则不可计算。这里只报告相关系数，不报告显著性 p 值。少于 50 组时明确标为试算。

技术定义参考：[scikit-learn 的 precision/recall 文档](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.precision_recall_fscore_support.html)、[SciPy 的 Spearman 文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.spearmanr.html)。
